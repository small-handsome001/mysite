服务器说「接受你的钥匙」，然后拒绝了我

2026-10-18 · Git / SSH

这是我目前见过最反直觉的报错：两句话摆在一起，前后矛盾。

现象

配置 GitHub 的 SSH 密钥，公钥明明贴到网页上了，推送还是失败：

$ ssh -vT git@github.com
debug1: Offering public key: id_ed25519
debug1: Server accepts key: id_ed25519        ← 服务器说：这把钥匙我认得
git@github.com: Permission denied (publickey) ← 然后拒绝了我

如果公钥没配对，日志里根本不会出现 Server accepts key。 它出现了，说明 GitHub 那边匹配上了。那为什么还是被拒？

真正的含义

SSH 登录不是「把钥匙递过去」就完事，而是三步：

  1. 你的电脑说：「我有一把钥匙，指纹是 XXX」
  2. 服务器查自己的名单：「查到了，你证明一下你真有私钥」← 这就是 Server accepts key
  3. 你的电脑用私钥签一段数据发回去 ← 卡在这一步

第 3 步失败了。失败的原因只有一个：私钥打不开。 而私钥打不开，最常见的原因是——它有密码，但程序没拿到密码。

根因：我给私钥设的密码是两个引号

生成密钥时我写的是：

ssh-keygen -t ed25519 -f id_ed25519 -N '""'

我以为 -N '""' 表示「不要密码」。 实际上 PowerShell 把这两个引号本身当成了字符串传进去， 于是私钥的密码变成了两个字符 " 和 "。

后面推送时程序拿不到这个密码，签名失败，于是出现了那个矛盾日志。

判据

以后看到这个组合，直接怀疑私钥：

Server accepts key  +  Permission denied (publickey)
        ↓
 服务器认得公钥，但你的私钥签不了名
        ↓
 查私钥有没有密码 / 文件是否损坏

不用去改 GitHub 设置，不用重新贴公钥，不用换端口。那些都是浪费时间。

验证方法

生成完立刻跑这一行：

ssh-keygen -y -f ~/.ssh/id_ed25519
  • 直接打印出一串 ssh-ed25519 AAAA... → 没有密码，正常 ✅
  • 光标停住、等你输入 → 有密码，后面一定会出事 ❌

这行命令的作用是「用私钥推导出公钥」。能推出来，说明私钥本身是完好的、不需要密码。

顺带一个问题：PowerShell 的空参数

PowerShell 调用外部程序时，-N "" 这种空字符串参数很容易被吞掉或者被当字面量。 稳妥写法是用 cmd 传： 

cmd /c ssh-keygen -t ed25519 -C "邮箱" -f "路径" -N ""

这个问题不只影响 ssh-keygen。凡是「参数里有空字符串」的场景，在 Windows 上都值得检查一次。

结论

日志不会撒谎，但它说的话需要翻译。 Server accepts key 不是「成功」，它只是「我看好你的钥匙，你还没证明它是你的」。

现在我的推送是这样： 

$ git push
To github.com:small-handsome001/mysite.git
   90cba40..334933f  main -> main
耗时 4.8 秒，没有输入任何密码
