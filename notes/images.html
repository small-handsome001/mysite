网页上的图片，我一次踩了三个坑

2026-10-11 · HTML

三个都不算难，但每个都让我花了半小时以上。

坑一：把 <img> 写进了 <head>

页面打开一片空白，图片跑到最上面，其他内容被挤到下面去。

<head>
  <meta charset="UTF-8" />
  <img src="assets/img/avatar.jpg" />   ← 错在这里
</head>

原因：<head> 里只放「给浏览器看的信息」—— 编码、标题、样式表链接。凡是要显示出来的东西， 都得放在 <body> 里。 <img> 是显示出来的东西，所以它属于 body。

怎么快速发现：F12 打开 Elements 面板，看图片节点在哪个父节点下面。 它长在 <head> 里就是错的。

坑二：文件名写了两个 .mp3

音频播放器一直是灰的，点播放没反应。 打开 F12 的 Network 面板，看到请求的是： 

track-01.mp3.mp3    404 Not Found

我在资源管理器里把文件改成了 track-01.mp3.mp3， 因为我以为「重命名」要把扩展名也一起打上去，结果 Windows 默认隐藏扩展名， 我打的那一次扩展名是多出来的第二次。

教训：404 永远先去 Network 面板看实际请求的路径， 不要在代码里瞎改。href 写错一个字母，表现和「文件不存在」一模一样。

坑三：一张没有 class 的图片，把卡片撑爆了

音乐页那张头像塞进了一个圆角小卡片里，结果卡片被撑得比整屏还高。

.card {
  padding: 20px 24px;
  border-radius: 12px;
}

/* 图片没有任何宽度限制，就按原始尺寸 720×1162 硬渲染 */

原因：图片不写 width，就按它的真实像素显示。 原图 720 像素宽，比卡片还宽，卡片自然被撑开。 

img {
  max-width: 100%;
  height: auto;
}

这三行是我现在所有网站的默认配置：图片永远不许超出容器。 它比给每张图单独设宽度可靠得多。

三个坑的共同点

它们都不是「语法写错」，语法完全合法，浏览器不会报错。 网页的很多错误是沉默的——页面照样打开，只是长得不对。

所以从这一课开始，我的习惯改成：任何「不对劲」都先按 F12， 看 Elements 和 Network 两块面板。肉眼调试是猜，看面板是证据。
