# 第 12 课 消除重复：一份页头，七个页面

## 一、先看你现在的债

你有 7 个页面，每个页面的 `<header>` 和 `<footer>` 都是**手抄的一份**：

```
index.html            header + footer
projects.html         header + footer
music.html            header + footer
notes.html            header + footer
notes/images.html     header + footer
notes/css-specificity.html  header + footer
notes/ssh-key.html    header + footer
```

**28 处重复。**

第 7 课你已经为这件事付过一次账了：

> 「四文件改四遍漏改」——你改了三个页面的 nav，忘了 `notes.html`，
> 结果那页缺「音乐」链接，是我截图才发现的。

**重复不是「麻烦」，是「会出错」。** 你改 N 遍，就 N 次忘记的机会。

还有一个现在的确存在的 bug，你可以自己去看：

```
index.html 的页脚：© 2025 幽林
其他 6 个页面：   © 2026 幽林
```

这就是重复的必然结果。

## 二、三种解法，本课选中间的

| 做法 | 优点 | 缺点 | 什么时候用 |
|---|---|---|---|
| ① 继续复制粘贴 | 简单，无 JS 也能看 | 改一次改 7 遍，必然漏 | 页面 ≤ 2 个 |
| ② **用 JS 生成（本课）** | 一处改全站变；无构建工具 | 禁用 JS 就看不到导航 | 你现在的量级 |
| ③ 模板引擎 / 框架 | 功能强 | 要 Node、要构建、要学新东西 | 以后真需要再说 |

第 ② 种的思路是：

> **页头不是「写出来的 HTML」，而是「用数据算出来的 HTML」。**

所以页头应该是一个**函数**：

```
数据（导航有哪些项） + 当前在哪个页面  →  函数  →  一段 HTML
```

**这正是第 11 课你练过的 map + join。** 同一个手艺，换个地方用。

## 三、核心代码：`layout.js`

文件在 `D:\my-site\layout.js`，看四个部分：

### 1. 数据

```js
const NAV_ITEMS = [
  { href: "index.html", text: "首页" },
  { href: "projects.html", text: "项目" },
  { href: "music.html", text: "音乐" },
  { href: "notes.html", text: "笔记" }
];
```

**以后加页面，只改这个数组。** 不用碰任何一个 `.html`。

### 2. 算出「当前在第几层目录」

```js
function getPrefix() {
  if (location.pathname.indexOf("/notes/") !== -1) return "../";
  return "";
}
```

根目录的页面，链接写 `index.html`；`notes/` 里的页面，链接要写 `../index.html`。

**这是相对路径的基本规则**：链接相对于「当前页面所在目录」，不是相对于网站根。

> 为什么不直接写 `/layout.js`（从根开始）？
> 因为你的网站地址是 `xxx.github.io/**mysite**/`，真实根是 `xxx.github.io/`。
> 写 `/layout.js` 会去找 `xxx.github.io/layout.js` → 404。
> **相对路径最稳，永远跟着文件走。**

### 3. 生成 HTML：map + join

```js
const links = NAV_ITEMS.map(function (item) {
  const isActive = item.href === current;
  const cls = isActive ? ' class="active"' : "";
  return `<a href="${prefix}${item.href}"${cls}>${item.text}</a>`;
}).join("");
```

比第 11 课多了两样东西：

- `${prefix}` —— 拼上级目录
- `class="active"` —— 给当前页加标记，CSS 里一改就高亮

### 4. 塞进页面

```js
const headerBox = document.querySelector("#site-header");
if (headerBox) headerBox.innerHTML = renderHeader(prefix);
```

`if (headerBox)` 是**防御**：万一某个页面忘了放盒子，脚本不会崩，只是不显示页头。

## 四、页面现在长这样

每个 `.html` 里，页头页脚从几十行变成两行：

```html
<body>
  <div id="site-header"></div>

  <main class="wrap">
    ...你自己的内容...
  </main>

  <div id="site-footer"></div>

  <script src="layout.js"></script>
</body>
```

**注意 `script` 的位置**：必须在两个盒子**后面**。放前面的话，脚本跑的时候盒子还不存在，`querySelector` 返回 `null`。

（第 6 课说过一次，这里又踩同一个坑——说明这条要记进肌肉记忆。）

## 五、代价：诚实地说清

用 JS 生成布局，有两个真实缺点：

1. **禁用 JS 的用户看不到导航。** 现在几乎没人禁用，但搜索引擎爬虫值得单独说。
2. **SEO 影响**：Google 会执行 JS，能抓到；但有些小爬虫不会。你的个人站不是商业站，**这个代价可以接受**。
3. **首屏闪一下**：HTML 到了先没有页头，JS 执行后出现。因为脚本在 body 末尾、文件很小，实际几乎看不见。

**如果哪天要做正经商业站，这种做法就要换成「构建时生成」**（比如把所有页面编译一遍，把页头写死进去）。那是第 ③ 种方案，现在不学。

## 七、坑速查

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 页头不显示，Console 报 `null` | `script` 放在盒子前面 | 把 script 挪到 `</body>` 前 |
| `notes/` 里的页面导航 404 | 没处理 `../` 前缀 | 看 `getPrefix()` 返回值 |
| 部署到 GitHub 后全站没样式 | 写成了 `/site.css` 绝对路径 | 改回相对路径 `site.css` |
| 当前页没高亮 | `getCurrent()` 拿到的文件名和 `href` 不一致 | Console 打印 `location.pathname` 看 |
| 页头闪一下才出现 | 正常现象（JS 生成） | 不用修，文件小就看不见 |
