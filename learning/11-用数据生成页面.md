## 零、先说这一课解决什么实际问题

打开你的 `music.html`，加一首曲子要做什么？

```html
<div class="track">
  <h3>断らなかった</h3>
  <p class="meta">原创 · MIDI 编曲</p>
  <audio controls src="assets/audio/track-01.mp3"></audio>
</div>
```

**复制这 5 行，改 3 个地方。** 加 10 首就是复制 50 行、改 30 个地方。

而且你会发现：

- 曲名打错一个字，要么全站不一致，要么你得挨个改
- 哪天想给每首曲子加个"播放次数"，你得再改 10 遍结构

**这一课就是把"内容"和"结构"分开**：

```
数据（曲名、年份、文件路径）  →  [ 一段渲染代码 ]  →  HTML
```

以后加曲子，**只改数据，不碰结构**。

---

## 一、数据长什么样

JS 里描述"一首曲子"，最自然是**对象**：

```js
const track = {
  title: "断らなかった",
  meta: "原创 · MIDI 编曲",
  file: "assets/audio/track-01.mp3"
};
```

多首就是**数组套对象**：

```js
const tracks = [
  { title: "断らなかった", meta: "原创 · MIDI 编曲", file: "assets/audio/track-01.mp3" },
  { title: "第二首", meta: "编曲练习", file: "assets/audio/track-02.mp3" }
];
```

> **这个结构你必须记熟**：`数组[下标].字段` → `tracks[0].title`。
> 它和 C++ 的结构体数组、Python 的 `list[dict]` 是同一个东西，**只是语法不同**。

---

## 二、把数组变成 HTML：`map` + `join`

### 第一步：`map` 把每个对象变成一段 HTML 字符串

```js
const html = tracks.map(function (t) {
  return `
    <div class="track">
      <h3>${t.title}</h3>
      <p class="meta">${t.meta}</p>
      <audio controls src="${t.file}"></audio>
    </div>
  `;
});
```

`map` 的意思是：**对数组里每一项，都执行一次这个函数，把返回值收集成新数组。**

```
[ 曲子1, 曲子2 ]  --map-->  [ "<div>...</div>", "<div>...</div>" ]
```

> 注意那个反引号 `` ` `` —— 这叫**模板字符串**。
> 只有它能让你在字符串里直接写 `${变量}`。用普通引号 `"..."` 是不行的。

### 第二步：`join("")` 把数组拼成一个字符串

```js
const html = tracks.map(...).join("");
```

不写 `join` 的话，得到的是「数组」而不是「一段 HTML」。`join("")` 用空字符串把它们粘起来。

### 第三步：塞进页面

```js
document.querySelector("#track-list").innerHTML = html;
```

`innerHTML` = **把这个元素里面整个换成这段 HTML**。

⚠️ **它会清空原有内容**。第一次用经常犯的错是写成了 `+=` 却忘了先清空，结果每次刷新都翻倍。

---

## 三、`innerHTML` 有安全风险，但你现在可以放心用

如果数据是**你自己写的**（像上面那样），`innerHTML` 简单直接，没问题。

**但如果数据来自用户输入或者网络**（比如有人在你网站的留言里写 `<script>`），`innerHTML` 会把它**当成代码执行**——这叫 XSS 攻击。

那时候的正确做法是用 `textContent` 或者 `createElement`：

```js
const h3 = document.createElement("h3");
h3.textContent = t.title;          // textContent 永远当纯文本
document.querySelector("#track-list").appendChild(h3);
```

| 方式 | 代码量 | 安全性 | 什么时候用 |
|---|---|---|---|
| `innerHTML` + 模板字符串 | 少 | ⚠️ 数据不可信时危险 | 数据结构固定（你现在的场景） |
| `createElement` + `textContent` | 多 | ✅ 永远安全 | 数据来自用户 |

**记住这条边界就够了：数据是自己写的，用 `innerHTML`；数据是别人给的，用 `createElement`。**

## 四、`fetch`：把数据放进单独的文件

数据写在 JS 里，加曲子还是要打开 `.js` 文件。

放进 `.json` 文件更干净：

```json
[
  { "title": "断らなかった", "meta": "原创 · MIDI 编曲", "file": "assets/audio/track-01.mp3" },
  { "title": "第二首", "meta": "编曲练习", "file": "assets/audio/track-02.mp3" }
]
```

然后**用 `fetch` 读它**：

```js
fetch("tracks.json")
  .then(function (res) { return res.json(); })
  .then(function (tracks) { render(tracks); })
  .catch(function (err) { console.log("加载失败", err); });
```

### 这三行必须理解的三件事

**1. `fetch` 是异步的**

它不是"立刻给你数据"，而是"**发出请求，稍后回调**"。所以数据永远在 `.then` 里面拿到，不在下面那一行。

```js
fetch("a.json").then(function (d) { /* 数据在这里 */ });
console.log("这行会先执行");        // ← 先打印
```

**2. 两层 `.then`**

| 第一层 `res` | 第二层 `tracks` |
|---|---|
| HTTP 响应对象（状态码、头部、一堆方法） | 解析后的 JS 数据 |
| `res.json()` 把响应体解析成数据，**返回的是 Promise** | 所以还得再 `.then` 一次 |

漏掉第二个 `.then` 是最常见的错。

**3. `.catch` 收尾**

文件路径写错、服务器没开、JSON 语法错——全走 `.catch`。**不写 `.catch`，出错时页面一片空白，也不会告诉你为什么。**

## 五、必须知道：`fetch` 不能用 `file://` 打开

如果你双击 `11-demo.html` 直接在浏览器打开（地址栏是 `file:///D:/...`），`fetch` 会失败：

```
Access to fetch at 'file:///...' from origin 'null' has been blocked by CORS policy
```

因为浏览器认为"本地文件之间互相读取"是危险的。

**这正好回到第 1 课**：`file://` 和 `http://` 是两回事。要用 `fetch`，就必须通过服务器访问：

```
双击 D:\my-site\启动服务器.bat
→ http://127.0.0.1:8123/learning/11-demo.html
```

**这条错误你一定会遇到至少一次。看到 `CORS` 或 `origin 'null'`，第一反应就是「我用 file:// 打开的」。**

## 九、这一课要记住的五句话

1. **内容用数据描述，结构用代码生成**。加东西只改数据。
2. **`map` 负责"每个都变一次"，`join` 负责"粘起来"。**
3. **`fetch` 是异步的**，数据在 `.then` 里，不在下一行。
4. **`innerHTML` 简单但有 XSS 风险**：数据是自己写的可以用，别人给的必须用 `textContent`。
5. **`fetch` 必须走 `http://`**，`file://` 会被 CORS 拦——这是第 1 课的延续。
