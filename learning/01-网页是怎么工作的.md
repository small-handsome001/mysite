# 第 1 课 · 网页是怎么工作的

## 一、真相

浏览器**不会**自己去读你的硬盘。它做的是：

```
浏览器 --"给我 index.html"--> 服务器 --"喏，内容"--> 浏览器 --自己画出来--> 屏幕
```

两个关键点：
1. 浏览器只负责**请求文件**，它得先知道文件在哪（这就是"路径"）。
2. 画成什么样由**浏览器决定**，同一份 HTML 在不同浏览器里略有差别。

Python 类比：`requests.get(url)` 时的你就是客户端；浏览器干的是同一件事，
只是它拿到 HTML 后直接**画出来**，而不是交给你处理。

> HTML 不是编程语言，是**标记语言**。没有变量、循环、判断。
> 浏览器不"执行"它，只"理解并画出来"。

## 二、三个文件的分工

| 文件 | 管什么 | 类比 |
|---|---|---|
| `.html` | 结构：标题、段落、图片 | 房子框架 |
| `.css` | 样式：颜色、字号、排列 | 装修 |
| `.js` | 行为：点击后发生什么 | 水电电器 |

## 三、`file://` vs `http://`

| | `file://`（双击） | `http://`（服务器） |
|---|---|---|
| 谁给文件 | 浏览器自己读硬盘 | 一个程序给 |
| 和真实网站一致吗 | ❌ | ✅ |
| 后果 | 媒体、JS 模块、fetch 会被安全策略拦住 | 正常 |

`127.0.0.1` = 本机自己。`8123` = 端口号。

## 四、起服务器

```powershell
cd D:\my-site
python -m http.server 8123
```

`-m` = 把一个 Python 模块当脚本跑。`http.server` 是**标准库自带**的极简服务器，不用装任何东西。

看到 `Serving HTTP on 127.0.0.1 port 8123` 就成功。**这个终端别关**，Ctrl+C 停止。

## 五、用 F12 看浏览器到底拿了什么

1. F12 → **Network** → F5 刷新
2. 看到 `01-first-page.html`，Status **200**
3. 点进去看 Headers：Request URL / Status Code

**这就是"请求-响应"过程的实时录像。** 以后 90% 的文件加载问题都靠它定位。

`200` = 找到了；`404` = **服务器好好的，但那个文件不存在**（去查路径，别重启服务器）。
