# 第 10 课 响应式：让同一个页面在手机上也好看

> 上课时间：2026-10-18
> 前置：第 1~9 课全部通过，网站已上线

---

## 零、先说清楚这一课要解决什么

第 5 课你写了三个页面，第 7 课变成四个页面，第 9 课上线。
**这些全程都是在 1000px 宽的浏览器窗口里完成的。**

而你的访客：

```
台式机     1920 × 1080
笔记本     1440 × 900
iPad        820 × 1180
iPhone      390 × 844     ← 你的页面在这里是什么样？
```

上一轮我发现了一个真实 bug：**390px 下右上角"笔记"被截断，页面能横向滚动**。
那不是"手机端不好看"，那是**坏了**——横向滚动条意味着内容跑出了屏幕。

这一课就是把"坏了"变成"好看"。

---

## 一、响应式不是魔法，是三件事

很多人以为响应式要装框架、写特殊语法。其实只有三件事：

| 要做的事 | 手段 |
|---|---|
| 1. 告诉手机「按真实宽度渲染，别假装自己是 980px」 | `<meta name="viewport">` |
| 2. 让宽度能伸缩，不要写死 | `%` / `max-width` / `flex` / `clamp()` |
| 3. 伸缩到放不下时，换一种排布 | `媒体查询 @media` |

**第 1 条你已经有了**（每页 `<head>` 里那行 viewport）。

> **为什么缺了它会出大事**：早期手机浏览器为了显示桌面网站，会假装自己有 980px 宽，
> 然后把整页缩小塞进屏幕——字小得像蚂蚁。viewport 那一行的意思是
> 「我是 390 就是 390，别装」。**这是移动端所有样式的前提。**

---

## 二、工具一：宽度别写死

你现在的 CSS 里，宽度基本都是"父母决定"，这是好习惯。要补两个地方：

### 图片

```css
img {
  max-width: 100%;
  height: auto;
}
```

`max-width: 100%` 的意思不是"永远 100%"，而是"**最多不超过容器，但小图不会强行放大**"。
这个区别很重要：

| 写法 | 大图 | 小图 |
|---|---|---|
| `width: 100%` | 缩到容器宽 | **被拉大，变糊** |
| `max-width: 100%` | 缩到容器宽 | 保持原样 ✅ |

### 音频播放器

```css
audio {
  width: 100%;          /* 你现在写的，没问题 */
  max-width: 100%;
}
```

播放器是浏览器原生控件，宽度给 100% 就够。但如果你在别处用了 `<video>`，
同理要加 `max-width: 100%`，否则视频会按原始分辨率撑破页面。

## 三、工具二：`flex` 放不下就换行

你上一轮已经被这个坑咬到了：

```css
.site-header {
  display: flex;
  justify-content: space-between;
}
```

**flex 默认不换行。** 空间不够时它不会"掉到下一行"，而是**把子元素压缩到极限，还不行就溢出**。

两种解法：

```css
/* 解法 A：允许换行 */
.site-header {
  flex-wrap: wrap;     /* 放不下就折行 */
  gap: 8px 24px;
}

/* 解法 B：手机上直接改方向（你现在用的这个） */
@media (max-width: 600px) {
  .site-header { flex-direction: column; align-items: flex-start; }
}
```

**什么时候选哪个？**

- 导航、标签栏 → 允许折行（A），因为折行后还是"一排链接"
- 名字 + 头像、标题 + 按钮 → 改方向（B），因为竖排更合理

## 四、工具三：媒体查询（本课重点）

```css
/* 屏幕宽度 ≤ 600px 时，括号里的规则才生效 */
@media (max-width: 600px) {
  .card {
    padding: 16px;
  }
}
```

### 断点怎么选

**不要背 768 / 1024 这些数字。** 正确的做法是：

1. 在浏览器里把窗口**从宽往窄慢慢拖**
2. 拖到某个宽度时，页面**变得难看**（文字挤、元素重叠、溢出）
3. **那个宽度就是你的断点**

因为断点的依据是**你内容的排版**，不是某款设备。你的网站三个卡片并排能撑到多窄，只有你的内容知道。

### 一个必须知道的顺序陷阱

```css
/* ❌ 错：这两条顺序颠倒，窄屏规则会被后面的默认值覆盖 */
@media (max-width: 600px) {
  .card { padding: 16px; }
}
.card { padding: 20px; }   /* 写在后面 = 赢 */

/* ✅ 对：媒体查询写在文件末尾（后面） */
.card { padding: 20px; }
@media (max-width: 600px) {
  .card { padding: 16px; }
}
```

这条规则和上一课笔记里讲的"权重"是同一件事的两个面：
**权重相同时，后写的赢。** 媒体查询本身不增加权重，所以它必须写在后面。

### mobile-first 还是 desktop-first

| 写法 | 含义 | 适合 |
|---|---|---|
| `max-width` | 先写大屏，再改小屏 | 已有一个桌面版，往小改 |
| `min-width` | 先写小屏（手机），再逐步增强 | 从零开始 |

**你现在是 desktop-first**（先写了桌面，后来补 `@media (max-width)`），这很正常，不用改。
但要知道：如果哪天你重做这个网站，**mobile-first 通常更省事**，因为手机样式最简单，先写简单的，再用 `min-width` 一层层加。

## 五、流体字号：`clamp()`

你现在的 `h1` 是 `36px`，在 390px 宽的屏幕上占得太多。

```css
h1 {
  font-size: clamp(24px, 6vw, 36px);
}
```

读法：**最小 24px，最大 36px，中间按视口宽度的 6% 走。**

| 视口宽 | `6vw` | 实际字号 |
|---|---|---|
| 390px | 23.4px | 24px（触底） |
| 500px | 30px | 30px |
| 600px 以上 | 36px+ | 36px（封顶） |

`clamp(最小, 弹性, 最大)` 三个参数缺一不可。它比写三条媒体查询省事，
**适合标题、超大数字**；正文不建议用（正文字号变化会让人读得累）。

## 六、分享卡片（`og:` 标签）

你把网址发给别人，微信/QQ/Twitter 会自动抓一个预览：标题、描述、缩略图。

**不写这几个标签，抓到的就是空白或者乱码。**

加在 `index.html` 的 `<head>` 里：

```html
<meta name="description" content="幽林：计算机专业大一，手写的个人网站。" />

<!-- Open Graph：微信、QQ、Facebook、Discord 等读这一套 -->
<meta property="og:title" content="幽林 | 主页" />
<meta property="og:description" content="计算机专业大一，在学 HTML 和 Python，业余作曲。" />
<meta property="og:image" content="https://small-handsome001.github.io/mysite/assets/img/avatar-web.jpg" />
<meta property="og:url" content="https://small-handsome001.github.io/mysite/" />
<meta property="og:type" content="website" />
```

三个要点：

1. **`og:image` 必须是完整网址**（`https://...`），不能写相对路径。因为抓取的人不在你的域名下。
2. 图片建议 **1200×630 左右**，至少 200×200，**否则某些平台不显示**。
3. `name="description"` 是给搜索引擎看的，`property="og:*"` 是给社交平台看的，**两套都要**。

> 验证方法：把网址粘到 https://www.opengraph.xyz/ 之类的预览工具里看效果。
> 注意：改了之后平台有缓存，可能要等几小时才会更新。

## 七、怎么验收（这是本课最重要的动作）

**别靠猜。** 两个方法，按顺序用：

### 方法 1：浏览器设备模式

F12 → 左上角那个"手机/平板"图标（`Ctrl + Shift + M`）→ 顶部选 iPhone 12 Pro 之类。

好处：能模拟真实设备像素比、触摸事件。
坏处：某些版本会上报错误的视口宽度，**不可全信**。

### 方法 2：iframe 拼图（我用的这个，更可靠）

我做了个工具：`learning/10-width-test.html`，里面塞了 4 个 iframe，
宽度分别是 320 / 390 / 768 / 1024。

**为什么它可靠**：媒体查询是按 iframe 的宽度计算的，不是按浏览器窗口。
所以你能在一屏里同时看到四种宽度下的效果，而且一定是真实渲染。

```bash
# 先开服务器
双击 D:\my-site\启动服务器.bat

# 然后访问
http://127.0.0.1:8123/learning/10-width-test.html
```

### 检查清单（逐条看）

- [ ] 没有横向滚动条（最右边缘有没有被切掉）
- [ ] 没有文字溢出容器
- [ ] 图片没有变形（不是被拉扁）
- [ ] 点击目标够大（链接/按钮手指能点到，不小于 40×40）
- [ ] 任何一行文字没有长到需要横向滑动

## 九、进阶（选做，不做也行）

1. 把 `max-width: 600px` 的媒体查询改写成 `min-width: 600px` 的 mobile-first 版本，体会顺序差异
2. 给 `.avatar` 加 `aspect-ratio: 1 / 1; object-fit: cover;` 替代写死的 `height`
3. 学 `srcset`：给同一张图准备 240 / 480 两个尺寸，让浏览器自己挑

## 十、这一课要记住的五句话

1. **viewport 是移动端一切的前提**，缺了它其他全白搭。
2. **宽度别写死**：`max-width: 100%` 比 `width: 100%` 安全。
3. **flex 默认不换行**，放不下就溢出——这是最常见的移动端 bug 来源。
4. **断点看内容，不看设备**。拖窗口拖到难看的那一下，就是断点。
5. **媒体查询写在后面**，因为权重相同时后写的赢。
